## Behavior detail

### Block (both)

1. (both) State: `pos` (default `center`), `facing` (default north), `waterlogged` (default false). `getRenderShape` = MODEL (block model, no special renderer).
2. (both) Placement: if the clicked face axis is Y — `UP` face → `pos=up`, `DOWN` face → `pos=down`, and facing is set to the player's horizontal look direction; otherwise `pos=center`, facing = opposite of the clicked face. Water at the placement spot sets `waterlogged`.
3. (both) `getShape`: `up` = top 10px full; `down` = bottom 6px full; `center` = 6px slab on the facing side (north: z 0–6, south: z 10–16, east: x 10–16, west: x 0–6).
4. (server) Right-click with empty hand: if the block entity is a terminal and `canInteractWith(player, false)` → `player.openMenu(entity)`; else chat message `chat.toms_storage.terminal_out_of_range` = "Terminal out of range". Always returns SUCCESS.
5. (both) `canConnectFrom(dir)`: true iff `dir` equals the terminal face direction — `facing`, or `up`/`down` when `pos` is `up`/`down`. `nextScan`: exactly one candidate face, the block adjacent to that face, with the opposite direction as the connection direction.
6. (both) Waterlogged: keeps water source and schedules the water tick.
7. (server) Ticker: `TickerUtil.createTicker(world, false, true)` (see 01-core `platform-layer.md`).

### StorageTerminalBlockEntity (server)

8. (server) On load: reads `facing`/`pos` from the block state, resolves the face direction (up/down override), and calls `itemCache.onLoad(level, pos.relative(d), d.getOpposite(), this)` — the "inventory" is the block on the other side of the terminal face.
9. (server) `updateServer` (every tick): if `updateItems` flag (set by `getStacks()`): get access via `NetworkInventory.getAccess`, get the change tracker; if the tracker value changed, rebuild `items` (map `StoredItemStack → TerminalItemStack`, merged by identity via `TerminalItemStack.merge`) — parallel stream if `Config.runMultithreaded`, else sequential merge; clamp `slotCount`/`freeCount` to 0…32767; `changeCount++`. Then clear the flag.
10. (server) Beacon scan gate: `level.getGameTime() % 40 == Math.abs(worldPosition.hashCode()) % 40` — when true, scan the inflated(8) region, take the max `BeaconLevelCalc.calcBeaconLevel` over beacon blocks, else −1. `TERM-04`: if `hashCode() == Integer.MIN_VALUE`, `Math.abs` stays negative, the comparison can never hold, and the beacon level is never computed.
11. (server) `canInteractWith(player, menuCheck)`: false if the block entity at the position is not this one. Reach d = 6; `termReach` = range from a WirelessTerminal in the player's inventory (0 if none). If `Config.wirelessTermBeaconLvl != -1` and `beaconLevel >= that` and `termReach > 0`: interactable — but if `Config.wirelessTermBeaconLvlCrossDim != -1` and `beaconLevel >= crossDim` → any dimension; otherwise same dimension only. Else `d = max(d, termReach)`; if `menuCheck`, `d += d/4`; pass if same dimension and squared distance to block center ≤ d².
12. (server) `pullStack(StoredItemStack, max)` / `pushStack(...)`: delegate to `NetworkInventory.getAccess(...)` → `pullMatchingStack` / `pushStack`; return null (not EMPTY) when nothing moved; `pushOrDrop` pushes and drops the remainder at block center; `dropItem` drops at block center.
13. (server) `getStacks()` sets the `updateItems` flag and returns the live map — the menu reads it in `broadcastChanges`.
14. (server) NBT save/load as listed in Data formats; `saveAdditional` always writes all three ints (no conditional write).

### CraftingTerminalBlockEntity (server)

15. (server) Adds a 3×3 `CraftingMatrix` (onChanged → `onCraftingMatrixChanged` + `setChanged`, but not while loading) and a `ResultContainer`. `onCraftingMatrixChanged`: if no current recipe or the current recipe no longer matches, re-look up (`getRecipe` — polymorph-aware: if `StorageMod.polymorph` and a `polymorphPlayer` weak ref is set, `PolymorphHelper.getRecipe(player, CRAFTING, input, level)`; else `recipeManager.getRecipeFor`). Result slot = `recipe.assemble(input)` or empty; notifies all registered menus (`onCraftMatrixChanged` → per-server-player `ClientboundContainerSetSlotPacket` for the 10 crafting slots).
16. (server) `craft(player)` — called when the player takes from the result slot (via `Result.onTake`, server side only): for each grid cell of the recipe's positioned input: consume 1 from the cell (if any); if the cell is now empty but was filled, re-pull 1 of the consumed item from the terminal; if that fails and `modes & 0x20` (pull-from-player-inventory is on), scan the player's whole inventory for a same-item-same-components stack and remove 1 (marks `playerInvUpdate`); if still empty and a remainder item exists, put the remainder in the cell. Remainder items that don't fit back are pushed to the terminal, then to the player inventory, then dropped at the block. Finally `craftingCooldown += result.count`.
17. (server) `clear(player)` (Clear Grid button, menu button id 0): for each grid slot, remove without update; push to terminal; remainder to player inventory; final remainder dropped. Then recompute recipe.
18. (server) `polymorphUpdate(player)` (menu button id 1): store `polymorphPlayer` weak ref, clear the cached recipe, recompute.
19. (server) `updateServer`: super, then `craftingCooldown = 0` (every tick).
20. (server) On block removal: `preRemoveSideEffects` drops the whole crafting grid as item entities. The block itself calls `Containers.updateNeighboursAfterDestroy` (redstone) on removal.
