## Behavior detail

### Menu (server unless noted)

1. Slot layout: `addStorageSlots(5, 8, 18)` — storage slots are `SlotStorage` records (display position + `TerminalItemStack` reference), kept in `storageSlotList`, **not** added to the menu's real `slots` list. Player slots via `addPlayerSlots(inv, 8, 120)`: 27 main + 9 hotbar (indices `playerSlotsStart+1`…`playerSlotsStart+36`) and an offhand slot (player inv index 40) drawn at a fixed offset. Every real slot is wrapped in `SlotData` for the tall-mode offset (`setOffset(x,y)` shifts `slot.x/y` from the recorded base).
2. `stillValid`: `te == null || te.canInteractWith(player, true)` (menu reach = 7 blocks, see terminal-blocks).
3. `broadcastChanges` (server): `sync.update(te.getChangeCount(), te.getStacks(), player, searchDiff)` — sends the item list only when the change count or search changed (01-core `terminal-sync`); when the server's last search differs from the client's, the tag also carries `s` = last search string.
4. `receiveClientNBTPacket` (client): `sync.receiveUpdate` → `itemList`; if `noSort` (ghost freeze active) only the counts are updated in place on `itemListClient`, otherwise `itemListClient` is replaced; `itemsLoaded = true`; `s` → `this.search`; then `onPacket` (screen button refresh).
5. `quickMoveStack` (server): shift-click on any player slot (index > `playerSlotsStart`, i.e. main/hotbar/offhand) → push the whole stack to the terminal (`te.pushStack`), remainder back in the slot, `broadcastChanges`. Shift-click elsewhere → `shiftClickItems` → EMPTY (no-op in the plain terminal).
6. `onInteract(clicked, act, mod)` (server; `SlotAction` values from 01-core):
   - `SPACE_CLICK`: for i in `playerSlotsStart+1` … `playerSlotsStart+27`: `quickMoveStack` (moves main+hotbar contents into the network, offhand excluded).
   - `PULL_OR_PUSH_STACK`: if carrying → push carried into network (remainder stays carried); else pull one full max-stack of the clicked item into the carry.
   - `PULL_ONE`: with modifier (SHIFT): pull 1, `moveItemStackTo` into player slots, pushOrDrop the overflow. Without: if carrying a matching stack with room → grow carried by 1 after pulling 1; else pull 1 into the carry.
   - `GET_HALF`: if carrying → split half of the carry (min 1) and push it; else pull half (min 1) of min(quantity, maxStackSize) into the carry.
   - `GET_QUARTER`: same with a quarter.
   - default (`SHIFT_PULL`): pull a full max-stack, `moveItemStackTo` into player slots (excluding offhand: end index `slots.size()-1`), pushOrDrop overflow, mark player inventory changed.
7. `receive` (server): `s` → `te.setLastSearch`; `sync.receiveInteract(message, this)` dispatches the slot action; child `c` → `te.setSorting(s)`, `te.setSearchType(st)`, `te.setModes(m)` (persisted).
8. `getRecipeBookType` = CRAFTING; `handlePlacement` = NOTHING.

### Screen (client)

9. Constructor args: (textureSlotCount=5, guiHeight=202, slotStartX=7, slotStartY=17).
10. `init`: tall mode → guiSize = 202−90 = 112; rowCount = (screenHeight−30−112)/18 (min 5); imageHeight = 112+rowCount×18; `menu.setOffset(0, (rowCount−5)*18)` and `menu.addStorageSlots(rowCount, 8, 18)`. Default mode: rowCount = 5, no offset, `addStorageSlots(5, 8, 18)`. `inventoryLabelY = imageHeight−92`. Offhand slot x: right-handed −26 (drawn left of the hotbar), left-handed 186 (right side).
11. `onPacket` (also called from `init` of `StorageTerminalScreen` to sync buttons on open): `controllMode = (modes & 0xF) % 3` (AE/RS/DEF); `sortingType = SortingTypes.VALUES[sorting & 0xFF]` — **`TERM-02`: no bounds check; a stale/edited NBT `sorting` value ≥ 6 (and < 256) throws `ArrayIndexOutOfBoundsException` when the GUI opens**; `reverseSort = (sorting & 0x100) != 0`; `ghostItems = (sorting & 0x200) == 0` (ghost on unless the bit is set); `tallMode = (modes & 0x10) != 0`; search-type bit 1 → focus the search field; bit 2 → load the server's stored search into the field once (until the text changes).
12. `sendUpdate` (client): sends `c` = {`s` = sort ordinal | reversed 0x100 | ghost-off 0x200, `st` = searchType, `m` = `writeModes()` = controllMode & 0xF | tall 0x10}.
13. `updateSearch` (every client tick via `containerTick`): parse the search text (syntax in Data formats); sort `itemListClient` with `sortingType.create(reverseSort)` (or the frozen comparator while `noSort`); `scrollTo(0)` and `currentScroll = 0` whenever the text changes; search-type bit 4 (sync) → `IAutoFillTerminal.sync(text)`; bit 2 (keep) → send `s` to the server. `isSmartItemSearchOn` = (searchType & 8) == 0.
14. Ghost mode (SHIFT + ghost button on): while SHIFT is held and `itemsLoaded` and not already frozen — build an index map of the current (sorted) list, set `menu.noSort = true`, and swap the comparator to "by index in the frozen list"; releasing SHIFT restores the normal comparator and `noSort = false` (refreshing `itemListClient` from `itemList`).
15. Scrollbar drag: while the left button is held inside the scrollbar region, `isScrolling`; `currentScroll = clamp((mouseY − regionTop − 7.5) / (regionHeight − 15), 0, 1)`.
16. `mouseScrolled`: when `needsScrollBars` (sorted count > rowCount×9): `i = (size+8)/9 − 5` — **`TERM-01`: the 5 is hardcoded, so in tall mode the wheel step is wrong (should be rowCount)**; `currentScroll = clamp(currentScroll − delta/i, 0, 1)`.
17. `scrollTo(f)` (menu side): row offset j = round(f × ((size+8)/9 − rowCount)); fill each of the rowCount×9 display slots from `itemListClientSorted[l + (k+j)*9]`.
18. Click on a storage slot: resolve the slot id under the mouse; action chosen per control mode (ControllMode AE/RS/DEF): pull-normal = left click (all modes); pull-half = right (AE/RS) or right-when-not-carrying (DEF); pull-one = right+SHIFT (AE), middle (RS), right-while-carrying (DEF); transfer-one = right+SHIFT+CTRL (AE — code comment notes this differs from real AE), middle+SHIFT (RS), right+SHIFT (DEF); SPACE key held while the mouse is not over a slot → `SPACE_CLICK`. Carried stacks push on left click (`PULL_OR_PUSH_STACK`).
19. Rendering: background drawn in three bands in tall mode (top 112px, bottom 90px, middle strip repeated) with a floating offhand slot sprite (`widget/floating_slot`, 32×32, at offhand x−8); each storage slot renders a count-1 stack plus the quantity text at 0.6 scale (white, yellow 0xFFFFFF00 when 0) via `NumberFormatUtil.formatNumber`; beacon icon at (leftPos+176, topPos+24+rowCount×18) when `beaconLvl ≥ 0` with tooltip `tooltip.toms_storage.terminal_beacon` = "Beacon level: %d%s" plus `terminal_beacon.anywhere` ("This terminal is accessible anywhere\nwith the Advanced Wireless Terminal") or `terminal_beacon.sameDim` ("...anywhere\nin this dimension\n..."); stat icon (16×10 at (leftPos+176, topPos+4)) hover tooltip: `terminal_stat.slots` = "All slots: %s", `terminal_stat.free` = "Free slots: %s (%s%%)", `terminal_stat.unique` = "Unique items: %s" — values formatted by `NumberFormatUtil`, "Alot (>32k)" (`terminal_stat.alot`) when the value is 32767, and the free percentage is `Math.round(free/slot*100)` — **`TERM-03`: no zero guard; an empty network with slotCount 0 gives 0/0 = NaN → rounds to 0, so "0%"** (Infinity → huge number if free>0 with slot=0, which cannot happen). Slot hover: when count > 9999 or sort is SPACE_EFFICIENCY, tooltip `tooltip.toms_storage.amount` = "Item Amount: %d" and `tooltip.toms_storage.slots_used` = "Used Slots: %d".
20. Tooltips for carried/ghost stacks are cached in the three `LoadingCache`s (tooltip lines, component patch lines, tag lines), 5 s expire-after-access.
21. Keyboard: ESC closes; TAB → vanilla (recipe book focus); everything else is consumed by the search field when it has focus. Middle click on the search field clears it.
22. `getExclusionAreas`: Box(leftPos−30, topPos, 30, imageHeight) — the button column is excluded from recipe-book hit areas.
23. Drag support: `getHoveredSlot` returns a synthetic `FakeSlot` (position `Integer.MIN_VALUE`, `allowModification` false) for the storage slot under the mouse so vanilla drag/click handling works on non-real slots.
