## Behavior detail

All steps are **(client)**.

### `ClientUtil`

1. **Tooltip extension**: `tooltip(key, consumer, args)` / `tooltip(key, addShift, consumer, args)` build translatable components (the `addShift` variant appends the hold-shift hint) (ClientUtil.java:44-57) and accept them into the passed-in `Consumer` (ClientUtil.java:44-57); the `tooltipExt` array is filled separately by `setTooltip(Component...)` (ClientUtil.java:59-62); `collectExtraTooltips(stack, list)` appends the stored components to an item's tooltip list (ClientUtil.java:64-66) (wired to `ItemTooltipEvent` on NF / `ItemTooltipCallback` on FB) (NF/StorageModClient.java:93-96; FB/StorageModClient.java:148-150). `multilineTooltip(text, objects)` splits a translated string on literal backslash characters and joins the parts as separate literal lines (ClientUtil.java:197-199).
2. **`drawTerminalOutline`**: returns unless the player holds a wireless terminal (main or off hand, via `WirelessTerminalItem.isPlayerHolding`) (ClientUtil.java:74); raytraces up to `Config.get().wirelessRange` blocks (fluids hit; VR raytrace first when `Platform.vivecraft`) (ClientUtil.java:77, :88-94); if the hit block state's block is in `StorageTags.REMOTE_ACTIVATE`, submits line geometry for the block's **occlusion shape** (not bounding box) in white alpha 0.4, line width 2 (ClientUtil.java:79-84).
3. **`drawConfiguratorOutline`**: returns unless the main (then off) hand holds the inventory configurator (ClientUtil.java:102-104); reads its `ConfiguratorComponent` (ClientUtil.java:106):
   - If the component is **not** selecting and not showing the inventory box → `drawPaintedHighlights` (step 4) and return (ClientUtil.java:107-110).
   - Otherwise, for every position in `component.selection()`: a unit-cube line box, white alpha 0.4 (ClientUtil.java:114-122).
   - If `massSelect()` and the current hit result is a block: an `AABB.encapsulatingFullBlocks(boxStart, hitPos)` line box in yellow (1, 1, 0) alpha 0.4, rendered with the no-depth pipeline (ClientUtil.java:124-134).
   - If the component is bound: the bound block's unit line box in red (1, 0, 0) alpha 1, no-depth (ClientUtil.java:135-143).
4. **`drawPaintedHighlights`**: streams `BlockPos.betweenClosedStream(AABB(player.pos).inflate(7))` (15×15×15); skips positions with `distanceToSqr > 49`; for each `IConfiguratorHighlight` block state, collects its highlight `VoxelShape` + `getHighlightColor()`; alpha = 1.0 while `dist² ≤ 25`, else `1 − (dist²−25)/24`; draws each shape's edges as lines in the paint color (ClientUtil.java:146-179).
5. **`drawShape`**: per voxel-shape edge, two vertices with normalized edge direction as normal, color + alpha, line width 2 (ClientUtil.java:183-195).
6. **`renderLineBox`** (three overloads): emits the 12 edges of a box (from two corners or an `AABB`) (ClientUtil.java:201-246).
7. **`drawConfiguratorOverlay`**: the HUD overlay (registered as the GUI layer above all) — draws the configurator's current mode/selection info (its text lines use the `tooltip.toms_storage.config_overlay.*` lang keys, e.g. ClientUtil.java:279-301; ClientUtil.java:248-307).

### `CustomRenderTypes`

1. `LINES` (registered pipeline): `RenderPipeline.builder(RenderPipelines.LINES_SNIPPET)` + `DepthStencilState(CompareOp.ALWAYS_PASS, false)` (always passes depth, no depth write) at location `toms_storage:pipeline/lines`; registered through `StorageModClient.registerPipeline`, which also assigns it to Iris `ShaderKey.LINES` when Iris is loaded (so shaders can override it) (NF/StorageModClient.java:138-144; FB/StorageModClient.java:168-174).
2. `LINES_NO_DEPTH`: a `RenderType` over `LINES` with `LayeringTransform.VIEW_OFFSET_Z_LAYERING` and `OutputTarget.ITEM_ENTITY_TARGET` (CustomRenderTypes.java:28-34); used for the configurator's mass-selection and bound-box lines so they draw regardless of world geometry occlusion.

### `ViveCraftHelper`

1. `rayTraceVR(maxDist, hitFluids)`: when `VRState.VR_RUNNING` and the VR player data exists and the player is **not seated**, returns `vrPlayer.rayTraceBlocksVR(worldRender, 0, maxDist, hitFluids)`; else `null` (ViveCraftHelper.java:9-17) (caller falls back to the normal `player.pick`).

### `StorageModClient` (NeoForge)

1. `preInit(mc, bus)` (mod bus): registers the 8 menu screens (NF/StorageModClient.java:66-75) (`storageTerminal`, `craftingTerminal`, `levelEmitter`, `inventoryLink`, `itemFilter`, `tagItemFilter`, `invConfig`, `filingCabinet` → their screens); registers `registerPipelines`, `registerOverlays`, `registerClientExtensions`; registers the Cloth config screen factory (`IConfigScreenFactory` → `ConfigurationScreen`) (NF/StorageModClient.java:56-64).
2. Game bus (registered in common init): `getTooltip` (→ `ClientUtil.collectExtraTooltips`), `renderWorldOutline` (`SubmitCustomGeometryEvent` → `drawTerminalOutline` + `drawConfiguratorOutline`), `clientTick` (→ `openTerm.consumeClick()` → `NetworkHandler.openTerminal()`) (NF/StorageModClient.java:77-79, :117-131).
3. `registerScreens`/`initKeybinds` (`RegisterKeyMappingsEvent`): `openTerm = new KeyMapping("key.toms_storage.open_terminal", IN_GAME, KEY_B, Category.GAMEPLAY)` (NF/StorageModClient.java:98-101; FB/StorageModClient.java:136-137).
4. `bakeModels` (`ModelEvent.ModifyBakingResult`): for `paintedTrim`, `invCableFramed`, `invProxy`, `invCableConnectorFramed`, replaces every possible block state's baked model with `new BakedPaintedModel(block, existingModel)` (NF/StorageModClient.java:103-115) (see [painted-models.md](painted-models.md)).
5. `registerOverlays` (`RegisterGuiLayersEvent`): the `CONFIGURATOR_OVERLAY_ID` layer above all → `ClientUtil.drawConfiguratorOverlay` (NF/StorageModClient.java:81-87).
6. `registerClientExtensions` (`RegisterClientExtensionsEvent`): `PaintedExtension` for the same 4 painted blocks (NF/StorageModClient.java:89-91).
7. `registerPipelines` (`RegisterRenderPipelinesEvent`): forces `CustomRenderTypes` class init, then registers the collected pipelines (NF/StorageModClient.java:133-136).

### `StorageModClient` (Fabric, `ClientModInitializer`)

1. `onInitializeClient`: `MenuScreens.register` for the same 8 menus (FB/StorageModClient.java:65-72); `ClientPlayNetworking` receiver for `DataPacket.ID` (FB/StorageModClient.java:74-78) (routes to the open screen if it implements `IDataReceiver` — the screen-data sync, area `01-core`/`03-terminal`); `ModelLoadingPlugin` that wraps the 4 painted blocks' models in `UnbakedPaintedModel` (FB/StorageModClient.java:80-93, :157-166); `BlockColorRegistry` for the same 4 blocks: when the block entity is a `PaintedBlockEntity` with a non-air `getPaintedBlockState()`, it queries the facade state's tint sources and adds each `colorInWorld` result (FB/StorageModClient.java:95-112); `LevelRenderEvents.END_MAIN` → `drawTerminalOutline` + `drawConfiguratorOutline` (FB/StorageModClient.java:114-121); login receiver `toms_storage:config` (see Data formats); `openTerm` keybind via `KeyMappingHelper` (same key `B`); the Polymorph widget registration call (commented out — `INT-08`, area `05-integration`) (FB/StorageModClient.java:154).
