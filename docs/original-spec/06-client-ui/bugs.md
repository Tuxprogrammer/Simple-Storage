## Suspected bugs

| ID | Title | Location | What looks wrong | Severity |
|---|---|---|---|---|
| `UI-01` | 11 narrator keys referenced in code are missing from all lang files | `NeoForge/src/platform-shared/resources/assets/toms_storage/lang/en_us.json` (missing `narrator.toms_storage.{terminal_sort, terminal_sort_rev, terminal_control, terminal_ghost_items, terminal_tall_mode, priority, add, removeAll, side, skip, removeFilter}`) | Screen readers hear the raw key strings for the terminal sort/reverse, control-mode, ghost-mode, tall-mode buttons and all configurator buttons (referenced in `AbstractStorageTerminalScreen` and `InventoryConfiguratorScreen`) | cosmetic |
| `UI-02` | EnumCycleButton narration key constructed dynamically, exists for no value | `NeoForge/src/platform-shared/java/com/tom/storagemod/screen/widget/EnumCycleButton.java:26` | `narrator.toms_storage.button_state.<state name lower-cased>` is built for every state (sort types, control modes, priorities, directions) but no `button_state.*` key exists in any lang file, so the appended state is always the raw key | cosmetic |
| `UI-03` | TextFieldElement uses a missing key from the wrong mod namespace | `NeoForge/src/platform-shared/java/com/tom/storagemod/util/PopupMenuManager.java:163-165` | `Component.translatable("tooltip.toms_trading_network.textfield", ...)` — namespace `toms_trading_network` (a different Tom's mod), key absent from all lang files; `TextFieldElement` is also never instantiated in this mod (dead code) | cosmetic |
| `UI-04` | EnumCycleButton NPE if pressed before first state set | `NeoForge/src/platform-shared/java/com/tom/storagemod/screen/widget/EnumCycleButton.java:45` | the press handler dereferences `getState().ordinal()`; `state` starts null and is only set by the screen calling `setState` in render-state extraction — a press before the first render frame NPEs (edge case; screens set state during init/render) | crash |
| `UI-05` | ListWidget scrollbar grab area is hard-coded and misses the drawn indicator | `NeoForge/src/platform-shared/java/com/tom/storagemod/screen/widget/ListWidget.java:62-65,84-87` | the grab rect is fixed at `x+56 .. x+70`, `y-1 .. y+57`, but the indicator is drawn at the right edge (`x + width − 6`) and travels `height − 9` px; on the 114-px-wide inventory-link list the drawn thumb (x+108) and the grab area (x+56..x+70) do not overlap, so dragging the scrollbar is unreliable | gameplay |
| `UI-06` | PopupMenu click rects are offset from the rendered tooltip position | `NeoForge/src/platform-shared/java/com/tom/storagemod/util/PopupMenuManager.java:45-73` | `extract` renders the menu as a tooltip anchored at `(x−12, y+12)` (plus the tooltip's own margins), but `mouseClick` hit-tests entry i at `(x, y+i*10, 100×8)` — the click target is shifted ~12 px right and ~12 px up from what is drawn, so the first/last entries are easy to misclick | visual |
| `UI-07` | IconButton base narration is empty | `NeoForge/src/platform-shared/java/com/tom/storagemod/screen/widget/IconButton.java:25` | the constructor passes `Component.empty()` as the `Button` name (the real name is kept only in the `name` field), so the default narration message carries no text; only `EnumCycleButton` overrides `createNarrationMessage`, leaving plain `IconButton`s (e.g. the configurator add/remove buttons) silent to screen readers | cosmetic |
