## Behavior detail

### WirelessTerminalItem (basic)

1. (both) `use(world, player, hand)`: raytrace from the player with reach `Config.get().wirelessRange` (blocks), partial tick 0, **fluids included** (WirelessTerminalItem.java:37). If the hit block state is in tag `toms_storage:remote_activate` (WirelessTerminalItem.java:39):
   1. (both) `Platform.checkUse(world, hit, player, hand)` — posts a synthetic `RightClickBlock` event (NF) / invokes the `UseBlockCallback` (Fabric); if canceled, its cancellation result is used (WirelessTerminalItem.java:40).
   2. (both) Otherwise (not canceled) `state.useWithoutItem(world, player, hit)` runs the block's normal right-click (WirelessTerminalItem.java:41) (e.g. the terminal opens its menu — which re-checks reach via `canInteractWith`, range-and-sync.md).
   3. (both) In all cases of a `remote_activate` target the item use returns `InteractionResult.SUCCESS_SERVER` — see `WIRE-01` (WirelessTerminalItem.java:42).
   If the target is not in the tag, the vanilla item use runs (typically nothing).
2. (server) `getRange(player, stack)` = `Config.get().wirelessRange` (WirelessTerminalItem.java:53-56) (this is what the terminal's reach check uses when the player carries the item — anywhere in the inventory, not only in hand).
3. (server) `open(sender, stack)` = no-op; `canOpen(stack)` = false (WirelessTerminalItem.java:58-65) — the keybind open flow (range-and-sync.md) therefore skips basic terminals.
4. (client) `isPlayerHolding(player)`: true if the main-hand **or** off-hand item is a basic wireless terminal — gates the client-side target outline (06-client-ui) (WirelessTerminalItem.java:48-51).
5. (client) Tooltip (shift-gated, via `ClientUtil.tooltip`): without SHIFT one italic gray line "Hold SHIFT for more info."; with SHIFT the lines of `tooltip.toms_storage.wireless_terminal` ("Extends your reach for the terminal." + "Reach: %d blocks", `%d` = `wirelessReach`) (WirelessTerminalItem.java:32; ClientUtil.java:48-56; en_us.json:49).

### AdvWirelessTerminalItem (advanced)

6. (both) `use(world, player, hand)` → `activateTerminal(world, stack, player, hand)` with the stack from the used hand:
   1. (both) No `bound_pos` component → `PASS` (AdvWirelessTerminalItem.java:63-64, :86) (an unbound advanced item does nothing on right-click — binding is done on a block, step 8).
   2. (client) Bound → `CONSUME` (AdvWirelessTerminalItem.java:82-83) (prevents double processing; the server decides).
   3. (server) Bound: resolve the bound dimension (`world.getServer().getLevel(pos.dim())`) (AdvWirelessTerminalItem.java:69). If the chunk at the bound pos is **loaded** (AdvWirelessTerminalItem.java:70): read the block state there; if it is in `remote_activate`, run `state.useWithoutItem(termWorld, player, hit)` with a synthetic `BlockHitResult` (pos, UP, pos, inside=true) and return its result (AdvWirelessTerminalItem.java:71-75); otherwise send action-bar message `chat.toms_storage.terminal_invalid_block` ("Invalid block") (AdvWirelessTerminalItem.java:77; en_us.json:172). If the chunk is **not loaded**, send `chat.toms_storage.terminal_not_loaded` ("Terminal out of range (Not Loaded)") (AdvWirelessTerminalItem.java:80; en_us.json:174). In both message cases the use falls through to `PASS` — see `WIRE-03`. Note: no `Platform.checkUse` synthetic-event step here (unlike the basic item).
7. (server) `useOn(context)` (right-click a block while holding the item): if **sneaking** (`isSecondaryUseActive`) (AdvWirelessTerminalItem.java:90-91):
   1. (client) → `CONSUME` (AdvWirelessTerminalItem.java:102-103).
   2. (server) if the clicked block is in `remote_activate`: set the `bound_pos` component to `WorldPos(level.dimension(), clickedPos)`, send action-bar `chat.toms_storage.terminal_bound` ("Bound Advanced Wireless Terminal"), return `SUCCESS` (AdvWirelessTerminalItem.java:95-100; en_us.json:171).
   3. Otherwise `PASS`. (Rebinding simply overwrites the component; there is no unbind.)
8. (server) `getRange(player, stack)` = `Config.get().advWirelessRange` (AdvWirelessTerminalItem.java:108-111). `open(sender, stack)` = `activateTerminal(sender.level(), stack, sender, MAIN_HAND)` (the keybind path, range-and-sync.md) (AdvWirelessTerminalItem.java:113-116). `canOpen(stack)` = true (AdvWirelessTerminalItem.java:118-121).
9. (client) Tooltip: the base line comes from `ClientUtil.tooltip("adv_wireless_terminal", ...)` with `addShift=true` (AdvWirelessTerminalItem.java:38; ClientUtil.java:44-56) — without SHIFT only the italic gray "Hold SHIFT for more info." placeholder shows; with SHIFT the lines of `tooltip.toms_storage.adv_wireless_terminal` appear ("Sneak + Right Click on a terminal to bind it." / "Range: %d blocks" (`%d` = `advWirelessRange`) / "The teminal's chunk has to be loaded" — typo, `WIRE-02`) (en_us.json:82).
   - Beacon lines, also shift-gated (passed with `addShift=false`, so they appear only while SHIFT is held) (AdvWirelessTerminalItem.java:39-45; en_us.json:83-85): if `wirelessTermBeaconLvl != -1`: `tooltip.toms_storage.adv_wireless_terminal.beacon` ("A nearby beacon in an 8 block radius of the terminal" / "extends the range of the terminal." / "The beacon's level determines the range:") then `...beacon1` ("%d: anywhere in the same dimension.", `%d` = `wirelessTermBeaconLvl`); if `wirelessTermBeaconLvlCrossDim != -1` also `...beacon2` ("%d: anywhere across dimensions.", `%d` = `wirelessTermBeaconLvlCrossDim`).
   - If the item is bound: `tooltip.toms_storage.adv_wireless_terminal.bound` — "Bound to (%s, %s, %s) in %s" with x, y, z and the dimension identifier string — appended directly, so it shows regardless of SHIFT (AdvWirelessTerminalItem.java:46-53; en_us.json:86).
   - Always: `tooltip.toms_storage.adv_wireless_terminal.keybind` — "Press the %s key to open", where the argument is `...keybind.outline` ("[%s]", GREEN) wrapping the keybind display name of `key.toms_storage.open_terminal` (AdvWirelessTerminalItem.java:54; en_us.json:87-88, :224).
10. (both) Crafting (data-driven recipes, 01-core API-MAP territory): `wireless_terminal` — shaped `PCP / aGg / PEP` (P = `#minecraft:planks`, a = `minecraft:spyglass`, C = `minecraft:comparator`, E = `#c:ender_pearls`, G = `#c:dusts/glowstone`, g = `#c:glass_blocks/colorless`) (data/toms_storage/recipe/wireless_terminal.json:3-15). `adv_wireless_terminal` — `minecraft:smithing_transform` upgrade: base `wireless_terminal` + `minecraft:netherite_ingot` with `minecraft:netherite_upgrade_smithing_template` (data/toms_storage/recipe/adv_wireless_terminal.json:2-8).

## On 1.15 / On 1.16

- **On 1.15** (`src/main/java/com/tom/storagemod/item/ItemWirelessTerminal.java`): only the basic wireless terminal exists (no advanced item, no binding, no beacon mechanics). Activation is the same raycast + `REMOTE_ACTIVATE` tag check, but directly calls `state.onBlockActivated` (no synthetic-event step) and returns the raw result (no forced `SUCCESS_SERVER`). The item id was `ts.wireless_terminal`.
- **On 1.16** (`src/main/java/com/tom/storagemod/item/ItemAdvWirelessTerminal.java`): the advanced terminal exists with identical behavior, but the binding is stored in **item NBT**: `BindX`/`BindY`/`BindZ` (int) + `BindDim` (string, dimension id) instead of the `bound_pos` data component; the tooltip shows the bound line when the NBT contains `BindX`.
